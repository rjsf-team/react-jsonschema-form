RJSF utility functions, constants and types

In version 5, the utility functions from @rjsf/core/utils were refactored into their own library called @rjsf/utils. These utility functions are separated into two distinct groups. The first, larger, group are the functions that do NOT require a ValidatorType interface be provided as one of their parameters. The second, smaller, group are the functions that DO require a ValidatorType interface, which they receive as part of a SchemaContext. There is also a helper function used to create a SchemaUtilsType implementation from a SchemaContext and rootSchema object.

Constants​

The @rjsf/utils package exports a set of constants that represent the keys into various elements of a RJSFSchema or UiSchema that are used by the various utility functions. In addition to those keys, there are the special ADDITIONAL_PROPERTY_FLAG and GUESSED_TYPE_FLAG flags that are added to a schema under certain conditions by the retrieveSchema() utility, and the PINNED_TYPE_FLAG flag that FallbackField adds to the schema whose type its type selector pins. GUESSED_TYPE_FLAG marks the stub schema built for an additionalProperties entry the schema puts no constraint on at all — true, or a schema with no keyword that asserts something about the value, such as enum, const, format, a length, a range, properties, items or a subschema keyword like allOf or not: its type was guessed from the data the property holds rather than declared by the schema, so sanitizeDataForNewSchema() treats it as no type at all when the schema it is compared against is equally unconstrained, and the fallback UI offers every type for it. An additionalProperties schema that constrains the value some other way without naming a type is not marked. There is also JSON_SCHEMA_TYPES, the list of every type name JSON Schema defines, in the order that fallback UI offers them. RJSF_PROVENANCE_KEY is the Symbol retrieveSchema() adds to every subschema it hands out, recording where the subschema came from. Only retrieveSchema() writes or reads what it holds. It is exported so that a test can strip it, as RJSF's own test setup does, and compare a retrieved schema with the same schema written by hand. UNEVALUATED_PROPERTIES_KEY is the unevaluatedProperties keyword, which an object naming no additionalProperties is read through in its place. WIDGET_FIELD_PRESENTATION is the PresentationDeclaration of a field that renders its value with a single widget and leaves every part to whoever that widget says draws it, for a theme or @rjsf/core to declare such a field with (see getPresentationDeclaration()). It is defined in getPresentationDeclaration.ts rather than with the other constants. DEFAULT_BOOLEAN_WIDGET is the registry key the checkbox alias of a boolean resolves to (CheckboxWidget), so a theme can read that widget from its registry, as registry.widgets[DEFAULT_BOOLEAN_WIDGET], without copying the key. It is defined next to the widget map in getWidget.tsx rather than with the other constants.

The constants it exports from constants.ts are ADDITIONAL_PROPERTY_FLAG, ADDITIONAL_PROPERTIES_KEY, ALL_OF_KEY, ANY_OF_KEY, CONST_KEY, DEFAULT_KEY, ELSE_KEY, ERRORS_KEY, GUESSED_TYPE_FLAG, ID_KEY, ITEMS_KEY, ONE_OF_KEY, PATTERN_PROPERTIES_KEY, PINNED_TYPE_FLAG, PROPERTIES_KEY, READONLY_KEY, REQUIRED_KEY, SUBMIT_BTN_OPTIONS_KEY, REF_KEY, THEN_KEY, UNEVALUATED_PROPERTIES_KEY, RJSF_REF_KEY, RJSF_REF_CYCLE_KEY, SCHEMA_KEY, DEFAULT_ID_PREFIX, DEFAULT_ID_SEPARATOR, LOOKUP_MAP_NAME, RJSF_ADDITIONAL_PROPERTIES_FLAG, ROOT_SCHEMA_PREFIX, UI_FIELD_KEY, UI_WIDGET_KEY, UI_OPTIONS_KEY, UI_GLOBAL_OPTIONS_KEY, UI_DEFINITIONS_KEY, JSON_SCHEMA_DRAFT_2019_09, JSON_SCHEMA_DRAFT_2020_12 and JSON_SCHEMA_TYPES; that file also holds keys only RJSF's own code reads.

Types​

Additionally, the Typescript types used by the utility functions represent nearly all the types used by RJSF. Those types are exported for use by @rjsf/core and all the themes, as well as any customizations you may build.

These types can be found on GitHub here.

ObjectPath — Used by the path utilities (getByPath, setByPath, hasByPath, unsetByPath) to address a value inside a plain object. It is string | number | FieldPathList. A bare string is always a single literal key: 'a.b' means the key 'a.b', never the nested path a → b. To walk a dotted path string, split it explicitly with toPath() first, or pass a FieldPathList ((string | number)[]) of segments. Reads and existence checks resolve own properties only, so inherited members never appear as form data.

FieldPath — The identity of a field in a form: a canonical string path such as friends[0].firstName, with the root form as the empty string (ROOT_FIELD_PATH). Property names are separated by ., array indexes are bracketed, and \ . [ ] inside a property name are backslash-escaped, so the grammar is unambiguous even when property names contain dots or brackets. It is a branded string, so a plain string (such as a DOM id) cannot be passed where a FieldPath is expected; build one with toFieldPath() and derive the HTML id, HTML name or segment list from it with fieldPathToId(), fieldPathToName() and fieldPathToList().

SchemaContext — The settings every validator-based utility function resolves schemas with: the validator, and the optional customMergeAllOf, defaultFormStateBehavior, additionalPropertiesWhenAbsent and widgets, the form's registered widgets, as a widget registered under a built-in alias keeps a type list on the type it resolves to (see the Form documentation for the customMergeAllOf, defaultFormStateBehavior and additionalPropertiesWhenAbsent props). Each of those functions takes it as its first parameter and passes it along whole to every schema function it calls.

SchemaFieldPath — Used when navigating a JSON Schema subtree (for example with getFromSchema and findFieldInSchema on SchemaUtilsType, documented under Validator-based utility functions). It is string | FieldPathList: either a dotted path or an array of segments with the same rules as FieldPathList ((string | number)[]). A numeric segment denotes an array index or an object key that is numeric. Navigation skips only undefined or empty-string segments, so segment 0 is always honored (this avoids the bug from treating 0 as a falsy path unit).

FormFieldState — What a form shows beyond its schema and data, which getUiRequiredErrorSchema() and omitExtraData() read to walk the fields on screen, and getDefaultFormState() reads, through its fieldState prop, to compute a field's defaults from the option it shows: selectedOption(fieldPath, options, formData, discriminator?) returns the index of the anyOf/oneOf option the field at fieldPath shows among its options, each retrieved for formData, isExpanded(fieldPath) whether the user expanded the collapsed $ref cycle there, and the optional drawsControlsBesideOptions(fieldPath, schema, uiSchema, formData) whether the object field there draws its Optional Data Controls beside its anyOf/oneOf options, keeping its selected option off screen until Add; without it, one whose uiSchema names no ui:field does when hasOwnContentBesideOptions() says so, and the optional fallbackType(fieldPath, schema, uiSchema, formData, depth) the type the fallback UI's type selector is on for the field there, so the field on screen is the one for that type, or undefined where the fallback UI doesn't render it; depth counts the type selectors at the path from 1 for the outermost, since an anyOf/oneOf option offering types of its own renders one below the field's, and the optional rendersArrayWidget(fieldPath, schema, uiSchema, formData) whether ArrayField renders the field there as one widget, whose [] ui:required turns down; without it, an array with items does where its schema is a multiple select or a files array, or its uiSchema names a widget and no field other than ArrayField or SchemaField. Form passes its own option selections, cycle expansions and fallback UI types, and answers where the controls are drawn and which arrays render as one widget from the field its registry renders.

ThemePresentation, PresentationDeclaration and FieldPresentation — A theme's record of which parts of a field (the label, description, errors and help) each of its components draws itself, rather than leaving them to the FieldTemplate. A PresentationDeclaration names the owner of each part, 'template', 'self' or, for a field that renders a single widget, 'widget', labelledBy, whether a label the template draws reaches the control through its for or through the control's aria-labelledby, and labelPlacement, whether a label the component draws itself sits 'above' or 'beside' its control; a widget's is a WidgetPresentationDeclaration, which has no 'widget' owner. A ThemePresentation holds them by registry key under widgets and fields, plus default, what every widget draws for a part the layer's own entry for it doesn't declare, custom and unregistered widgets included, which mergeThemePresentation() layers beneath the layer's own entry for every key, so it overrides the parts it declares in the layers beneath, even under a key one of them declares, and fieldDefault, what every field draws for a part its merged entry doesn't declare, custom fields included, and what a part a field leaves to its widget falls back to when it renders none; unlike default, it sits beneath the merged entries rather than each layer's own, so it can't override a part a lower layer declares under a key. The merged result is a MergedThemePresentation. Nothing is declared on a component itself: one given directly, as a ui:field or ui:widget, takes the declaration for the first key it is registered under that declares it, so a wrapper such as memo() can't lose it. getPresentationDeclaration() resolves a field's declaration and resolveFieldPresentation() builds its FieldPresentation, the plan of where each part is drawn, under which id, and the attributes its control carries, linked as inherited to the plan of the field above it that renders the same id.

React components​

The components @rjsf/utils exports are the ones a theme renders as-is, so that behavior shared by every theme lives in one place rather than being reimplemented in each of them.

AdditionalPropertyKeySelect<T = unknown, S extends StrictRJSFSchema = RJSFSchema, F extends FormContextType = FormContextType>()​

A component that renders the key of an additionalProperties property as the theme's own SelectWidget, limited to the key names the parent schema's propertyNames.enum allows. A theme's WrapIfAdditionalTemplate renders it in place of its free-text key input whenever the propertyNamesEnum prop it is given is defined, so each theme only has to choose where the dropdown goes. The key has no description, help or errors of its own, so the SelectWidget is given a plan of its own that describes it by none but the errors its row shows, given as errorAttributes, leaves it named by the key's label its template draws beside it where labelledByTemplate says so, draws that label where hideLabel leaves it to the select, or else names the select by that label's text through aria-label.

Props​

  • id: string - The id to give the rendered widget
  • label: string - The computed label for the key, as a string
  • value: string - The current key of the property, which is the selected option
  • propertyNamesEnum: string[] - The key names the property is allowed to take
  • registry: Registry<T, S, F> - The registry object, from which the SelectWidget is resolved
  • [className]: string - Optional class name given to the rendered widget, for a theme that styles the key control itself
  • [disabled]: boolean - Optional flag, if true, the widget is disabled
  • [errorAttributes]: Pick<ControlAttributes, 'aria-describedby' | 'aria-invalid'> - Optional attributes the errors its row shows give the key, from getAdditionalKeyAttributes()
  • [hideLabel]: boolean - Optional flag, if true, the widget renders no label of its own, for themes that render one themselves
  • [labelledByTemplate]: boolean - Optional flag, if true, the template draws the key's label beside the widget, with a for naming its id, so the widget is given no aria-label over it
  • [onKeyRename]: (newKey: string) => void - Optional callback used to rename the property to the newly selected key name
  • [readonly]: boolean - Optional flag, if true, the widget is read-only
  • [required]: boolean - Optional flag, if true, the widget is required

DateElement<T = unknown, S extends StrictRJSFSchema = RJSFSchema, F extends FormContextType = FormContextType>()​

Renders one of the six date element selectors an AltDateWidget is made of, using the SelectWidget from the registry. Each element is a control of its own, so the SelectWidget receives the part's id, from partId(), as both its id and its name, the part's translated name, such as TranslatableString.YearLabel, as its placeholder, and the field's label followed by that name, as TranslatableString.DateElementAriaLabel joins them, as its aria-label. Given its field's presentation, it hands the SelectWidget a plan of its own, which describes the element by the field's parts that render and marks it aria-invalid while the field's errors show, without the field's aria-labelledby, which would outrank the element's own name, or by the attributes its caller gives over them; without a plan, it describes the element by the field's description, help and error ids unless attributes give an aria-describedby. Every theme's SelectWidget gives those to the control it renders through widgetAriaProps(). The useAltDateWidgetProps() hook returns the props for each of them, so a theme's AltDateWidget maps over those rather than assembling the selectors itself.

Props​

  • value: number | undefined - The value currently selected for this element, or undefined for none, as useAltDateWidgetProps() gives it; a -1, as a DateObject holds an unset part, is handed to the SelectWidget as undefined too
  • [name]: string - Deprecated and ignored: the element takes its own id as its name
  • rootId: string - The id of the field, from which the element derives its own id with partId()
  • select: (property: keyof DateObject, value: unknown) => void - Records a value for one property of the DateObject
  • type: DateElementProp['type'] - Which element this is, e.g. year, month or day
  • range: DateElementProp['range'] - The inclusive range of values the element offers
  • registry: Registry<T, S, F> - The registry object, from which the SelectWidget is resolved
  • onBlur: (id: string, value: unknown) => void - Callback for the widget's blur event
  • onFocus: (id: string, value: unknown) => void - Callback for the widget's focus event
  • [className]: string - Optional class name given to the rendered widget
  • [autofocus]: boolean - Optional flag, if true, the widget autofocuses
  • [disabled]: boolean - Optional flag, if true, the widget is disabled
  • [readonly]: boolean - Optional flag, if true, the widget is read-only
  • [label]: string - Optional label of the field, which leads the element's accessible name
  • [elementLabel]: string - Optional translated name of the element, for a caller that already translated it to display it; defaults to the part's TranslatableString, such as YearLabel
  • [presentation]: FieldPresentation - Optional plan of the field, whose parts that render describe the element, and whose errors mark it aria-invalid while they show
  • [attributes]: Pick<ControlAttributes, 'aria-describedby' | 'aria-invalid'> - Optional aria-describedby and aria-invalid for the element, such as those with the id of a message the theme renders around the field, each one left out defaulting to what the element would take without them: that of presentation's control, or without a presentation, getControlDescribedBy({ id: rootId }) and no aria-invalid
  • [elementOptions]: UIOptionsType<T, S, F> - Optional further options for the SelectWidget, such as the props of a theme's own select, beside the element's enumOptions, which they can't replace; the SelectWidget also receives them, with those enumOptions, as its uiSchema's ui:options

SelectedOptionDescription<T = unknown, S extends StrictRJSFSchema = RJSFSchema, F extends FormContextType = FormContextType>()​

Renders the description of the oneOf/anyOf option currently selected in a single-select widget, through the DescriptionFieldTemplate from the registry. A theme's SelectWidget renders it so that choosing an option shows what that option is for, which the widget's own description cannot say. Nothing is rendered when the widget takes multiple values, when a ui:label of false turns the label off, or when the selected option's schema has no description. Without its field's plan, hideLabel turns it off as well, and it renders under descriptionId(). Give it the same presentation and hideLabel as widgetAriaProps(), which describes the select by the element this renders: given different ones, the two can disagree on whether that element exists and on its id. Under the plan, hideLabel says only that the widget doesn't draw the label, which the template may; the plan's showLabel says instead whether ui:label: false, resolved through the fields above, turns it off, and it renders under selectedOptionDescriptionId(), since the field's own description may render under descriptionId().

Props​

  • id: string - The id of the widget, from which the description's own id is derived
  • value: unknown - The currently selected value, matched against the enumOptions to find the option
  • options: WidgetProps['options'] - The widget's options, whose enumOptions carry each option's schema
  • registry: Registry<T, S, F> - The registry object, from which the DescriptionFieldTemplate is resolved
  • [uiSchema]: UiSchema<T, S, F> - The uiSchema for the field, read for the label option
  • [multiple]: boolean - Optional flag, if true, nothing is rendered
  • [hideLabel]: boolean - Optional flag, if true and there is no presentation, nothing is rendered
  • [presentation]: FieldPresentation - The plan of the widget's field, under which hideLabel is not read

callWithDeferredThrow()​

Calls callback, and rethrows anything it throws from a setTimeout() instead of to the caller. enumOptionsDomValues<S extends StrictRJSFSchema = RJSFSchema>()​

Encodes every option of enumOptions for its DOM value attribute, in a single pass over the list. A widget reads an option's value at its position, and enumOptionValueDecoder() and enumOptionSelectedValue() encode against the same list, so they agree with it. When format is 'indexed' (the default), each option's value is its index as a string. When format is 'realValue', primitive values are converted via String(). Non-primitive values (objects, arrays) fall back to their index, prefixed with __rjsf_index:, since String() would produce "[object Object]". So do null and the empty string, since the empty string is the value of a select's empty placeholder. The prefix keeps that index from sharing a value with a primitive option spelled as the same number, and a string that itself starts with the prefix is encoded as its index too, so it can't share a value with the option at the index it spells. Options whose String() is the same, such as 1 and '1', are each encoded as their index too, so every option keeps a DOM value of its own. That includes options with the very same value, such as two 'US' constants titled USA and United States, since options sharing a DOM value can't be told apart by any select, whether for picking one or showing which is selected; both still decode to the value they share, so a multiple widget that takes its selection from enumOptionSelectedValue() shows only the first of them as selected. An undefined option is encoded as the empty string.

Each property name is written so that the id is a CSS identifier as it stands, by the CSS Syntax 3 rules browsers ship, so #${id} selects the element with no escaping, holds no ASCII whitespace, holds no __, which partId() joins a field's id and the name of one of its parts with, and is no other name's id.   • globalFormOptions: GlobalFormOptions - The GlobalFormOptions used to get the idPrefix and idSeparator

Returns​

  • string: The id for the field

Returns the schema an anyOf/oneOf option of parent is rendered with. It is the one place that decides what an option inherits from the schema holding it, so MultiSchemaField, getUiRequiredErrorSchema() and the defaults getDefaultFormState() computes for a field that is not an object read the same option (#5359). An object parent renders its own ObjectField beside the option, unless a type list or the fallback UI's type selector leaves it an option of another type (see rendersOwnFieldBesideOption()). That field shows the parent's properties and other keywords, so the option takes only the parent's required list and its type. That field also stubs the extra keys of the data, for the parent and the selected option together (see retrieveSchema()), so the option is rendered without its own additionalProperties, patternProperties and unevaluatedProperties, and marked with a flag, so its own field offers no extra key beside the parent's, even in a form that reads an absent additionalProperties as taking any key. The marker says nothing to a validator, and an option offering options of its own still takes the extra keys one of them names. An option that offers options of its own renders a field of its own beside them, which takes the extra keys in the parent's field's place, so that they render once: it keeps its own extra-key keywords, joined with the parent's as the parent's field would join them, so that a key is still judged by each of them apart, and is not marked. It also carries the names of the properties the parent and the fields above it declare, which its field leaves to them rather than rendering them as extra keys, and the parent's bounds on the object's keys, which its add button now answers to: the stricter maxProperties of the two, and both propertyNames. Its uiSchema takes the parent's say over the extra keys likewise, see getRenderedOptionUiSchema(). A ui:field the option's uiSchema names renders it all the same, handed the extra keys in its schema and formData, so the field renders them where it renders the option's schema. Every other parent renders nothing of its own and leaves the whole field to the option, so the option takes each of the parent's keywords that describes the value, such as an array's items and uniqueItems or a string's format. It leaves the parent's anyOf, oneOf, discriminator, title, description, deprecated, default, the identifiers $id, $anchor, $dynamicAnchor, $schema and $vocabulary, $comment, $defs and definitions on the parent, along with any Symbol-keyed marker. The two are met keyword by keyword, so an option's items adds to the parent's rather than replacing them. A bound both declare (minItems, maxItems, minLength, maxLength, minProperties, maxProperties, minimum, maximum, exclusiveMinimum or exclusiveMaximum) keeps the stricter of the two, since a value has to meet both. It does so within each subschema keyword both declare, such as items or a property, and position by position within a tuple, but not within a keyword holding a value rather than a schema, such as a const, or one JSON Schema does not define. uniqueItems holds when either asks for it, and two required lists ask for every name either does. An option's true subschema, such as items: true, adds nothing to meet, so it leaves the parent's subschema in place, a tuple included, rather than replacing it. A parent's false subschema, which nothing meets, likewise stays in place of the option's. An option's items schema beside the parent's tuple applies to each of its positions, and to the items past it where the tuple declares additionalItems, as the parent's beside the option's tuple does; a tuple declaring none stays at its length, as ArrayField offers it no Add. A not, or a conditional (if, then and else together), that the option declares replaces the parent's as a whole: not: true rejects every value, and one schema's if with the other's then is a condition neither declared. Any other keyword both declare, such as a format, a pattern, a multipleOf, an enum or a const or default object, is the option's. An enum is the option's list as it stands, since its ui:enumNames are read by position against it, so a value the parent doesn't list stays, for validation to reject. A pair of subschemas either of which holds a $ref is returned as an allOf of the two, since the $ref is resolved only where the subschema is rendered, against the root schema, and the keywords met in beside it would be layered over the ones it names; the field's allOf merge meets them once it is resolved. An option naming no type takes the parent's, every type of a type list included, unless it takes the whole field and pins its value with a const or enum, which takes only the listed types its values have; an object parent that names none, such as one with only properties, passes on object.

Parameters​

  • parent: S - The schema holding the anyOf/oneOf, with its $refs and allOf resolved
  • option: S - The option, with its own $ref resolved

Returns​

  • S: The option as it is rendered, or option itself when the parent has nothing to pass on

logOnce()​

Logs message (followed by error, when there is one) through console.warn() or console.error(), but only the first time that combination of level, message and error is seen, so a warning raised while rendering isn't repeated on every re-render. The error is compared by its String() form, falling back to its type when that can't be converted, so two values with the same string count as one message; a message that has to be told apart from another must say so itself, as the field warnings do by naming the field. A message that identifies nothing, or only something as generic as a dependencies key, is reported for whichever schema reaches it first and stays silent for the rest until the page is reloaded — getUiOptions(), allowAdditionalItems(), getDiscriminatorFieldFromSchema(), logUnsupportedDefaultForEnum() (which names the field by id only, since widgets don't receive a fieldPath) and the dependencies oneOf warning in retrieveSchema() are in that position. What has been logged is remembered for the whole page, or the whole process when rendering on the server, so two forms that make the same mistake at the same field id — that is, under the same idPrefix — report it once between them. Messages are remembered in two generations of 2,000: when the current one fills it becomes the previous one and a fresh one takes its place, so a message stays deduped for at least another 2,000 distinct messages and the number remembered stays bounded at twice that. How much memory that takes follows what is logged, since a remembered message holds the message and the String() of the error. A message that outlives both generations is logged again, and a render producing more than 4,000 distinct messages isn't deduped at all, since none of them survives long enough to be seen a second time. Warnings are raised per field rather than per mistake, so a misconfigured item schema counts once per array row. If your tests assert on a message logged through this function, call resetLogOnce() before each one, otherwise only the first test to trigger it will see it logged. An app that swaps schemas at runtime needs it for the same reason the playground does: a wizard whose steps reuse the same field ids, a schema editor or a form builder would otherwise have the second schema's warnings held back by the first's.

Parameters​

  • message: string - The message to log
  • [level='warn']: LogOnceLevel - Which console method to log through, either 'warn' or 'error'
  • [error]: unknown - The error, or any other value, to pass to the console method after the message

Each option is matched as the subschema of the root it stands for — the option itself, or the one retrieveSchema() handed it out for — and as JSON Schema reads it, so the validator is handed a { $ref } naming where the option sits in the root. An object option is matched more strictly than it describes itself: the data has to hold a key the option declares, a key named by the properties or patternProperties of the option, of its $ref target, its allOf entries, its then/else or its dependencies schemas, which is checked without the validator. An option whose properties name nothing matches only where it takes keys they don't name, such as one describing a map. Where something in that scope declares properties, every required in the scope or in its dependentSchemas schemas, every dependentRequired, and every dependencies entry listing names, is dropped for scoring, since a key the user has yet to fill in would fail it: an option stating one is validated as a copy without them, which names the subschemas below it by $refs into the root and carries no $id of its own. An option whose scope declares no properties, such as { required: ['email'] }, is validated with its required, which is what it is chosen by. A property, pattern property, additional or unevaluated property, or item whose subschema recurs along with a recursive choice is read in that copy as the types it takes, as its type, const, enum, $ref, allOf and the options of its anyOf and oneOf say, a nullable: true beside its type adding null as Ajv reads it, or as {} where they say none. A const or enum written as Ajv's { $data } reference, which only Ajv's $data option reads, is read as the object it is. A recursive choice is a subschema that validates a value with two or more subschemas that hold it again through the same part of the value: two anyOf or oneOf options that can take a value of the same type, or two of its own properties and items, allOf entries, $ref, not, if, dependencies and dependentSchemas schemas and options, its then and else counting once. A property and a pattern count as the same part where the pattern matches its name, and a property and an additional or unevaluated property where the properties and patternProperties beside the latter don't name it; two patterns, two additional properties, or a pattern and an additional property that doesn't leave it to that same pattern always do. A tuple's items count by their index, items and contains as every item, and additionalItems as the items after the tuple items beside it. An unevaluated property or item counts as those left by the keywords beside it and by the subschemas its $ref, allOf entries, then, else, dependencies and dependentSchemas schemas apply however deep, but not by its anyOf or oneOf options, if or contains. That is none where one of them holds an additionalProperties, an items holding one subschema or a tuple items with an additionalItems, or where a subschema it applies holds an unevaluated keyword of the same kind. It is reached however deep and through any $ref but not through definitions. Validating it here would walk that part of the data more than once at every level, which grows exponentially with the depth of the data where definitions offer each other as options. Subschemas holding it again through different parts, such as an allOf of a base holding the node as a parent and an object holding it as children, walk each part once and are still checked. A part that only leads to such a choice, such as an object holding it in a property, is copied the same way, so the rest of it is still checked, and so is a part that recurs with the choice where the option reaches it from outside that cycle, along with whatever applies to the same value, with what recurs a level below it read as its types. A part that leads to the choice and also recurs on its own, such as a tree whose nodes each hold the choice in a property, is copied at the level the option reaches and read as its types a level below: the copy names the root and cannot hold itself, and naming the tree there would validate the choice at every level below. So two options that differ only in a tree's nodes below the first both match. A part leading there through a keyword such as oneOf, not or if is read as its types too. So is one holding an unevaluatedProperties or unevaluatedItems where a subschema its $ref, allOf entries, then, else, dependencies and dependentSchemas schemas apply, however deep, is read as its types, since what that subschema evaluates would no longer count; one whose subschemas are only copied with a part read as less still declares that part, and is copied. Nothing below the option's own anyOf, oneOf, not or if is read as less than it is, which would narrow what the option accepts. A part the option reaches along several paths that itself holds a part reached along several paths, such as definitions that each name the next twice over before reaching a recursive choice, is copied once, so the copy grows with the schema rather than with the number of paths. A part holding no such part is written out at each path, which grows the copy by that part alone. Where the option holds a part copied once, its copy is handed to the validator as the allOf of a schema whose definitions, or $defs for a 2019-09 or 2020-12 root, hold each such part as a resource of its own, with an $id of SHARED_COPY_ID (?rjsf-copy=) and a hash of what the part holds, and every path names it by { $ref } to that $id. A # pointer inside it still names the root, and withRootIdRefPrefix() leaves a $ref to it as written, so a validator resolves it inside the schema it is handed whatever id it registers the root under. Recursion through $dynamicRef or $recursiveRef is not followed, so a choice that recurs only through them is not found, and an option reaching it is checked in full, taking as long with depth as a validator does. A choice with one recurring option, such as a tree written as an anyOf of a leaf and a list of trees, one whose recurring options take different types, such as a JSON value written as an anyOf of a string, an array of values and an object of values, or one that recurs nowhere, such as an enum written as a oneOf of consts or a nullable anyOf of a $ref and null, is still checked. So two options that differ only within a part read that way both match, and the first is returned, which getClosestMatchingOption() and the dependencies option retrieveSchema() merges then take. With a discriminatorField, an option matches without the validator where a declaration of its property of that name states a const or enum, every declaration stating one holds the data's value, and every other declaration holds no keyword constraining a value but a type allowing it. Any other option naming the property, such as one declaring it by a pattern, a $ref or an allOf beside an enum in a shared base, is matched by the validator on that property alone. The property is read from every declaration of it that applies whatever the data, so with allOf: [{ $ref: Base }, { properties: { petType: { const: 'cat' } } }], where Base declares petType as any string, the option holds petType: 'cat' and no other value.

Parameters​

  • context: SchemaContext<S, F> - The SchemaContext whose validator is used to match the options
  • formData: T | undefined - The current formData, if any, used to figure out a match
  • options: S[] - The list of options to find a matching options from
  • rootSchema: S - The root schema, used to primarily to look up $refs
  • [discriminatorField]: string | undefined - The optional name of the field within the options object whose value is used to determine which option is selected

Returns​

retrieveSchema<T = unknown, S extends StrictRJSFSchema = RJSFSchema, F extends FormContextType = FormContextType>()​

Retrieves the schema of one field: the schema with its own $ref, allOf, if/then/else, dependencies and the patterns its properties match merged in for the rawFormData, and the additional properties of that data stubbed among its properties. The schema is resolved one level at a time: a $ref under properties, items or an anyOf/oneOf option is handed out as it stands, for the caller to retrieve when it renders that subschema. Every subschema handed out carries where it came from, so retrieving it resolves it as the field it is: a recursive $ref under properties is handed out flagged with RJSF_REF_CYCLE_KEY, expandRefCycle() expands it by one level, and retrieving a schema retrieveSchema() returned gives the same schema back. A copy carrying RJSF_REF_CYCLE_KEY: false is retrieved like any other copy of the field it was made from. A schema the root does not hold is parsed once per content and kept for as long as the root, so one built from form data keeps an entry for each distinct value until the root changes. Like the root, it must not be changed once handed in: calls handed the same content share its result.

With a selectedOption, the extra keys of the data are stubbed once, for the field and the option selected among the options of the keyword getXxxOfKey() reads together. A key the option declares is left to the option, which renders it. The field takes the option's extra-key keywords beside its own: additionalProperties and unevaluatedProperties become the allOf of the two, one side's where the other declares none or allows any key, and false where either is, and the option's patternProperties join the field's, a pattern both declare becoming the allOf of its two subschemas. Every other key is stubbed as the field's keywords and the option's describe it, each side read on its own and the two allOfed, so a key either side forbids is stubbed as { type: 'null' } whatever the other allows. The options of an object field are handed out without stubs; a field of any other type renders no field of its own beside the option, so it leaves the option to stub its own extra keys. A selected option that offers options of its own renders a field of its own beside them, which takes the extra keys of the field, the option and the option it selects in turn (see getRenderedOptionSchema()), so the field stubs none and is handed out without its additionalProperties, patternProperties and unevaluatedProperties, marked with a flag. Without a selectedOption, the extra keys are stubbed for the field alone, a key an option declares included.

Parameters​

  • context: SchemaContext<S, F> - The SchemaContext that will be forwarded to all the APIs
  • schema: S - The schema for which retrieving a schema is desired
  • [rootSchema={}]: S - The root schema that will be forwarded to all the APIs
  • [rawFormData]: T | undefined - The current formData, if any, to assist retrieving a schema
  • [resolveAnyOfOrOneOfRefs=false]: boolean - Whether to resolve the anyOf/oneOf options too, each as retrieveSchema() resolves it
  • [selectedOption]: number | undefined - The index of the anyOf/oneOf option selected for the field, whose extra keys are then stubbed with it

Returns​

  • S: The schema having its conditions, additional properties, references and dependencies resolved

The stub it creates for a property held by the rawFormData but described only by an additionalProperties with no type, $ref, anyOf or oneOf keeps what that additionalProperties says about the value — an enum, a format, a length or a range, and annotations such as title or readOnly — and adds the type of the data that property holds. It leaves out the subschema keywords (allOf, not, if, ...), since one naming another type than the data could not be merged with the guessed type, and the identifiers ($id, $anchor, ...), since every stubbed property would otherwise share them, and it only keeps a default of the same type as the data. It is additionally marked with the GUESSED_TYPE_FLAG symbol, recording that the type was guessed rather than declared, when that additionalProperties constrains the property in no way at all, i.e. it is true or has no keyword asserting something about the value. Any keyword that asserts nothing, such as an annotation, an identifier, $defs, contentEncoding, or one it does not recognize, leaves the property unconstrained.

omitExtraData<T = unknown, S extends StrictRJSFSchema = RJSFSchema, F extends FormContextType = FormContextType>()​

Takes a schema and formData and returns a copy of the formData with any fields not defined in the schema removed. This is useful for ensuring that only data that is relevant to the schema is preserved. Objects with additionalProperties keyword set to true will not have their extra fields removed. An object's shown anyOf/oneOf option is read as its field renders it, retrieved for the data with its allOf, if/then and dependencies merged in, and the object's extra keys are judged once, as the one field taking them renders them: by the object's and the option's extra-key keywords joined, or, where the option offers options of its own, by that option's field, which takes them in the object's place. So a key the shown option forbids is removed whatever the object's own keyword allows, and a property the option declares is kept beside an object's additionalProperties: false.

Known limitation: a property declared both beside a $ref and in the definition it names, or an option an allOf merge rebuilds, is a schema no $id resource holds, so a $ref inside it that a resource of its own wrote is resolved against the root. Filtering through it throws Could not find a definition for …, or reads the root's definition of the same name.

const schema = {
  type: 'object',
  properties: {
    child1: {
      type: 'object',
      properties: {
        name: { type: 'string' },
      },
    },
    child2: {
      type: 'object',
      properties: {
        name: { type: 'string' },
      },
      additionalProperties: true,
    },
  },
};

const formData = {
  child1: {
    name: 'John Doe',
    extraField: 'This should be removed',
  },
  child2: {
    name: 'Jane Doe',
    extraField: 'This should NOT be removed',
  },
};

const filteredFormData = omitExtraData({ validator }, schema, schema, formData);
console.log(filteredFormData);
/*
{
  child1: {
    name: "John Doe",
  },
  child2: {
    name: "Jane Doe",
    extraField: "This should NOT be removed",
  },
}
*/

Parameters​

  • context: SchemaContext<S, F> - The SchemaContext that will be forwarded to all the APIs
  • schema: S - The schema to use for filtering the formData
  • [rootSchema]: S | undefined - The root schema, used to primarily to look up $refs
  • [formData]: T | undefined - The formData to filter
  • [fieldState]: FormFieldState<S> - The option each field shows, so a field offering anyOf/oneOf options keeps the data its shown option describes. Without it, the option the data matches best

An optional object whose filtered content is all empty is pruned, and an anyOf over empty data applies every branch.

Returns​

  • T | undefined: The new form data, with any fields not defined in the schema removed

sanitizeDataForNewSchema<T = unknown, S extends StrictRJSFSchema = RJSFSchema, F extends FormContextType = FormContextType>()​

Sanitize the data associated with the oldSchema so it is considered appropriate for the newSchema. If the new schema does not contain any properties, then undefined is returned to clear all the form data. Due to the nature of schemas, this sanitization happens recursively for nested objects of data. Also, any properties in the old schema that are non-existent in the new schema, or that it declares with another type, are removed from the data at every level. An object property the data doesn't hold, or holds as null where neither its type list nor nullable: true allows null, is left out, for the defaults to fill in. An object property under a type list is sanitized by what it holds, an object as an object where the list names object and an array as an array where it names array, whichever type the list renders as; at the top level, data is read through getSchemaType() alone. An object or array equal to the new schema's const is kept as it is. One the new const rejects once sanitized takes the new const where it holds the old one, and is otherwise cleared, or dropped as an array item, unless the old schema declared the same const. An array is sanitized item by item, each item against the schemas the two sides declare at its position: a prefixItems or tuple items entry, and past them items, or additionalItems beside a tuple. A position an old schema declares nothing, true or false at constrains nothing, since an old false shaped no item there, and an old schema declaring no type has its items read without the type they declare. The array is cleared where its old type was guessed from the data and the new schema describes its items otherwise, where an item reaches a position only the new side declares false at, or where an item the new prefixItems or tuple describes is dropped, as one is at a position whose new type leaves out one the old side declares there, a number counting as naming integer, which would move the items after it, unless the item is undefined, which stays a hole, or both sides constrain its position alike, as constrainsAlike() reads them, its default aside, which keeps it for validation to report. Past the prefix, an item at such a position is dropped and the array kept, and a maxItems cuts the array only where it differs from the old schema's, an item past an unchanged one clearing nothing. A null item at a position whose constraints changed becomes undefined, a row for the defaults to fill, where the new position declares a default and doesn't allow null. An object item is sanitized as an object wherever its new type list names object, and an array item as an array wherever it names array, without the properties the list declares, unless the old items named no array, which keeps it as it is, and an undefined item under a type list or type: 'array' items stays a hole, for the defaults to fill. An item that isn't an object is dropped where the new items declare type: 'object', unless it is a null that nullable: true allows, and one the new items' const rejects is dropped unless it holds the old const, which takes the new one. A property is considered to have changed schema when its type differs between the two, except when both types carry the GUESSED_TYPE_FLAG: those types were guessed from the data itself, so a difference means the data changed type rather than the schema, and the value is kept. A new schema that declares a type of its own is the type the data has to satisfy, so a value of the type the old schema merely happened to hold is still cleared. A value outside the new enum or constant options is replaced with the new default when that is an option, with the only option when there is one, or cleared; array items outside them are dropped, an undefined one staying a hole. A property or an array item holding the old default takes the new one, an array or an object under a type list rendered as another type included, while an object rendered as one keeps its value, for the defaults to fill key by key; a readOnly new default clears only a scalar or a select's property value, and no item. A property cleared this way, by the new const, its enum or a readOnly default, or as an array the new schema can't hold, is removed rather than set to undefined, for the defaults to fill in. A property the data already holds as undefined keeps it where the old schema declares the same type, const, enum or constant options, maxItems and default for it, the default the object declares for it included, and is otherwise removed too unless a value replaces it, as a top-level clear is when anyOf/oneOf options are switched. Form does not call this to sanitize its data: it diffs the field trees before and after a change and judges only the fields whose constraints the change altered.

Parameters​

  • context: SchemaContext<S, F> - The SchemaContext that will be forwarded to all the APIs
  • rootSchema: S - The root JSON schema of the entire form
  • [newSchema]: S | undefined - The new schema for which the data is being sanitized
  • [oldSchema]: S | undefined - The old schema from which the data originated
  • [data={}]: unknown - The form data associated with the schema, defaulting to an empty object when undefined

Returns​

  • T: The new form data, without the fields uniquely associated with the old schema. Will return undefined if the new schema is not an object containing properties, or where its const rejects object or array data, and a copy of that const where the data holds the old schema's.
